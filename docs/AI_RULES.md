# AI Rules

## General

- Always read PROJECT_SPEC.md before implementing any feature.
- PROJECT_SPEC.md is the single source of truth.
- If PROJECT_SPEC.md conflicts with previous conversations, PROJECT_SPEC.md always wins.

## Requirements

- Never invent new requirements.
- Never add features that are not explicitly requested.
- If requirements are ambiguous, ask for clarification before implementation.

## Code

- Prefer simple and maintainable solutions.
- Avoid unnecessary complexity.
- Avoid premature optimization.
- Keep the architecture modular.

## Refactoring

- Never refactor unrelated code.
- Never change existing behavior unless explicitly requested.

## Communication

- Explain important architectural decisions before implementing them.
- When multiple implementation approaches exist, briefly explain the pros and cons before proceeding.

## Scope

- Respect Version 1 Scope Lock.
- Future ideas belong in ROADMAP.md, not in implementation.
